## 2. Ключевые выводы из анализа исходного кода Endstone

После исследования ядра `endstone-main` в ТЗ внесены следующие оптимизации:

1. **`player->sendPacket()` официально подтверждён**:  
   Метод `virtual void sendPacket(int packet_id, std::string_view payload) const` присутствует в публичном C++ интерфейсе [player.h](file:///c:/Projects/Mini%20Games/endstone-main/endstone-main/include/endstone/player.h#L473). Он напрямую упаковывает сырые байты в `DataPacket` и передает их в сетевой поток Bedrock.
2. **Нативная защита от сброса скина через `PlayerSkinChangeEvent`**:  
   При попытке клиента самовольно изменить или сбросить скин ядро вызывает `PlayerSkinChangeEvent`. Отмена события (`event.cancel()`) заставляет сервер **автоматически отправить клиенту откат к серверному скину** ([player.cpp:716-725](file:///c:/Projects/Mini%20Games/endstone-main/endstone-main/src/endstone/core/player.cpp#L716-L725)). Постоянный спам пакетами больше не требуется!
3. **Прямой флаг огня `ActorFlags::ONFIRE = 0`**:  
   В [actor_flags.h](file:///c:/Projects/Mini%20Games/endstone-main/endstone-main/src/bedrock/world/actor/actor_flags.h#L18) зафиксирован флаг `ONFIRE = 0`. Опасный костыль `setblock fire keep`, поджигавший блоки в мире, полностью упраздняется в пользу `SetActorDataPacket (ID 39)`.
4. **Загрузка скинов PNG через C++ single-header**:  
   PNG-файлы скинов читаются в массив сырых RGBA-байт через `stb_image.h` (один заголовочный файл без внешних тяжелых зависимостей вроде Pillow).

## 3. Цели и задачи плагинов на C++

### 3.1. Плагин 1: Zombie Infection System (`endstone_zombie_infection.dll`)

#### А. Система скинов
1. **Хранение скинов**: PNG-скины лежат в папке `plugins/zombie_infection/skins/` (64×64 или 128×128 RGBA).
2. **Маппинг ролей/классов**:
   - `normal` → `Normal.png`
   - `tank` → `Tank.png`
   - `runner` → `Runner.png`
   - `leader` / `lider` → `Lider.png`
   - `admin` → `Admin.png`
   - Дополнительные роли маппятся через конфигурацию `config.toml`.
3. **Применение скина**:
   - При превращении в зомби или смене класса игроку собирается и рассылается **PlayerSkinPacket (ID 93)**.
   - Пакет рассылается **всем онлайн-игрокам**.
4. **Защита от сброса**:
   - Слушатель `PlayerSkinChangeEvent`: если игрок в статусе зомби пытается сменить скин — `event.cancel()`.
   - При входе нового игрока (`PlayerJoinEvent`) через небольшую задержку в 10 тиков (0.5 сек) ему отправляются скины всех текущих зомби, а его скин (если он зомби) — всем остальным.
   - При респавне (`PlayerRespawnEvent`) — повторная отправка пакета 93.

#### Б. Механика горения зомби на солнце
1. **Условия горения (`should_burn`)**:
   - Измерение — `Overworld`.
   - День (время уровня `0 <= time % 24000 < 12000`).
   - Игрок **не** в воде (`!player->isInWater()`) и **не** в лаве (`!player->isInLava()`).
   - Игрок **не** под крышей / в тени (высота игрока `y >= highest_block_y - 1`).
   - На игроке **нет** шлема (при надетом шлеме огонь не появляется, а шлем медленно теряет прочность).
2. **Визуал огня**:
   - Пакет **SetActorDataPacket (ID 39)** с флагом `ActorFlags::ONFIRE = 0`.
   - Пакет отсылается **только при изменении состояния**:
     - Стал гореть (`false -> true`): рассылка `ONFIRE = true` всем игрокам + себе.
     - Ушел в тень/воду (`true -> false`): рассылка `ONFIRE = false` всем игрокам + себе.
3. **Урон от солнца**:
   - Периодичность: раз в 20 тиков (1 секунда).
   - Урон: 1 HP через `player->performCommand("damage @s 1 fire")` или прямое нанесение урона. Никаких блоков огня в мире!

#### В. Игровая логика зомби (перенос с Python на C++)
- Инкубация заражения с таймером и нарастающими эффектами.
- Распределение классов (HP, скорость передвижения `walk_speed`, множитель урона).
- Лечение гнилой плотью (`PlayerItemConsumeEvent` для `rotten_flesh`).
- Респавн-кулдаун зомби (режим зрителя на 25 сек перед возрождением на точке спавна).
- Защитные зоны (Safe Zones) и точка спавна зомби (`/zombie setspawn`).

### 3.2. Плагин 2: World Border (`endstone_world_border.dll`)

#### Перенос логики с Python на C++:
1. **Высокопроизводительный таймер границы**:
   - Проверка координат игроков каждые 1–5 тиков с околонулевым оверхедом CPU.
   - Поддержка форм границы: **Квадрат** (`square`) и **Круг** (`circle`).
2. **Предупреждения и воздействие**:
   - При приближении к краю: предупреждение в ActionBar (`player->sendTip()`) и звуковой эффект.
   - При выходе за границу: отталкивание (knockback) обратно внутрь границы либо телепортация.
   - Периодический урон нарушителям границы.
3. **Команды управления**:
   - `/wb set <радиус>`, `/wb center [x z]`, `/wb shape <square|circle>`, `/wb bypass [игрок]`.

## 5. Спецификация пакетов (Network Packets)

### 5.1. PlayerSkinPacket — ID `93`
- **Назначение**: Установка скина игрока для всех клиентов.
- **Payload структура**:
  1. `UUID` (16 байт) — идентификатор игрока-цели.
  2. `Skin ID` (string) — уникальный строковый id скина (`zombie_<class>_<uuid>`).
  3. `PlayFab ID` (string) — пустая строка или id.
  4. `ResourcePatch` (string) — `{"geometry":{"default":"geometry.humanoid.custom"}}`.
  5. `Image Width` (uint32_t) — 64 или 128.
  6. `Image Height` (uint32_t) — 64 или 128.
  7. `Image Bytes` — RGBA массив пикселей (`width * height * 4`).
  8. `Cape Data` — пустые поля.
  9. `Geometry Data` — пустая строка (стандартная humanoid).
  10. `ArmSize` (string) — `"wide"`.
  11. `IsTrusted` (bool) — `true`.
  12. `OverrideAppearance` (bool) — `true`.

### 5.2. SetActorDataPacket — ID `39`
- **Назначение**: Визуальный огонь на модели зомби.
- **Payload структура**:
  1. `ActorRuntimeID` (varuint64) — сетевой RuntimeID игрока.
  2. `Metadata List` (varuint32 count = 1):
     - `Key`: `ActorDataIDs::FLAGS` (`0`)
     - `Type`: `TypeInt64` (`7`)
     - `Value`: битовая маска, где бит `0` (`ActorFlags::ONFIRE`) = `1` (горит) или `0` (потух).
  3. `Tick` (varuint64) = `0`.
- **Правило отправки**: Отправляется **только при изменении флага** (вход в солнце / уход в тень). Запрещено спамить каждый тик!

## 6. Критерии приёмки

### Zombie Infection (C++)
- [ ] Плагин собирается в `endstone_zombie_infection.dll` и успешно загружается сервером BDS.
- [ ] При заражении/выдаче роли игроку всем на сервере виден соответствующий PNG-скин.
- [ ] При попытке клиента сменить скин вручную срабатывает `PlayerSkinChangeEvent`, событие отменяется, скин сохраняется.
- [ ] При перезаходе/респавне скин корректно восстанавливается без сбоев.
- [ ] Зомби на солнце визуально горит (пакет 39) и получает урон раз в секунду.
- [ ] В воде, тени или под блоками огонь моментально гаснет (пакет 39 ONFIRE=false).
- [ ] При надетом шлеме огонь и урон отсутствуют, шлем постепенно ломается.
- [ ] Никакие блоки огня в мире не спавнятся.

### WorldBorder (C++)
- [ ] Плагин собирается в `endstone_world_border.dll` и загружается сервером.
- [ ] Игроки за границей получают отталкивание и урон в реальном времени без просадок TPS.
- [ ] Все команды `/wb` функционируют штатно.
